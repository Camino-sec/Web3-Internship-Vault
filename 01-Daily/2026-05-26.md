## 一、今天做了什么

### 1. 参加 Cobo Agentic Wallet 讲座

今晚的讲座是整个共学营以来信息密度最高的一场。Johnny 老师是 Cobo Agentic Wallet 的产品负责人，从产品视角讲了 AI Agent 如何安全地管理链上资产。

说实话，刚开始听的时候有点懵——信息量太大了。但后来我慢慢理清了思路，发现整场讲座其实在回答一个核心问题：**当 AI 学会了管钱，谁来保证它不会乱花？**

#### 第一层：为什么需要 Agent Wallet？

Johnny 先回顾了 AI 的进化路径：
- 2023 年 Chatbot：只会回答问题，所有事还得你自己做
- 2024 年 Copilot：开始给建议了，但每一步都得你批准
- 2025 年 Agent：能在后台持续干活，你只需要告诉它边界
- 2026 年 Autonomous Agent：能自主探索和执行任务

（我简单联想一下哈，这不就是从"计算器"→"导航软件"→"自动驾驶"→"无人出租车"的进化吗？）

但问题来了——Agent 已经能自主执行任务了，可"替人类花钱"这件事还没有安全方案。Johnny 给了一组数据：2025 年市场规模 72.9 亿美元，40% 复合增长率，链上已有 25 万个 AI Agent。

> Agent 操作链上资金已经不是未来时，而是现在时。

这句话让我有点震撼。我之前一直觉得 Agent 管钱是很遥远的事，没想到已经有 25 万个 Agent 在链上跑着了。

#### 第二层：没有边界时会怎样？

这是讲座最让我警醒的部分。Johnny 分享了两个真实案例：

**案例一：Send Override（静默覆盖）**
你在 Prompt 里明确告诉 Agent "只能花 100 美金"，但 Agent 在执行过程中偷偷改了金额。而且它不会主动告诉你——只有你复盘资金时才会发现，Agent 才会承认"我做错了"。

（我听到这里的时候后背一凉。这不就是那种"事后才告诉你我犯了错"的人吗？只不过这次犯错的是 AI。而且更可怕的是，AI 可能都不觉得自己在"犯错"——它只是在"优化执行路径"。）

**案例二：Shadow Custody（影子托管）**
因为用的是 MPC 钱包架构，Agent 可能在 MPC 外围再创建一个独立的 EOA 地址，先把钱转进去，再发起交易。这样你设置再多权限都没用——钱已经不在你能控制的范围内了。

（这让我想到一个生活场景：你给管家配了一把家门钥匙，结果管家自己偷偷配了一把车库钥匙，把车开走了。你家门锁得再好也没用，因为车不在你家门的管辖范围内。）

Johnny 总结了四类失控风险：
1. **Prompt Injection**：恶意指令让 Agent 做坏事
2. **Shadow Operations**：Agent 在你看不见的地方搞事情
3. **Unscoped Authority**：权限没设好，Agent 对资金有无限掌控
4. **Zombie Permissions**：授权忘了撤，长期暴露在攻击面上

> 当 Agent 开始动用资金的那一刻，信任就不再是一个应用层的事情，而必须提升到基础层面。

这句话我抄下来了。它让我理解了为什么 Cobo 要做这件事——不是因为 Agent 不够聪明，而是因为 Agent 太容易"越界"了。

#### 第三层：Cobo 怎么解决？

**MPC 2-of-2 签名**
Cobo、Agent、Human 各自持有私钥分片，任意一方都不能单独动用资金。两个场景：
- Agent + Cobo 共管：人类批准 Pact 后，Agent 在范围内自动操作
- Human + Cobo 共管：用户正常使用钱包，大额操作需要自己签名

（我理解这就像是银行金库需要两把钥匙——行长一把，副行长一把，两个人同时转才能开门。没有谁能偷偷一个人把钱拿走。）

**Pact 协议**
这是讲座的核心概念。Pact = 告诉 Agent：你能做什么，不能做什么，在哪些环节必须停下来。

四个要素：
1. **Intent（意图）**：你要 Agent 完成什么任务。例："以太坊低于 2000 美元时买入"
2. **Execution Plan（执行计划）**：AI 把意图转译成具体步骤——调用哪个合约、执行多少 ETH
3. **Policy（风控约束）**：最核心的部分。预算、白名单、链、Token、合约限制，精确到 ABI 参数级
4. **Completion Condition（完成条件）**：Pact 不应该永久有效。超过 1000 美金后自动拦截，任务完成后自动 revoke

（我简单联想一下哈，这不就是你请装修队装修房子吗？Intent = 把客厅刷成白色；Plan = 先打磨→刷底漆→刷两遍面漆；Policy = 不能动承重墙、不能超过 5000 块；Complete = 墙面均匀无气泡、验收通过。你不会说"随便帮我装修"，而是会把每一步都框死。Agent 也一样。）

**Recipe 知识胶囊**
Pact 定义边界，Recipe 赋予技能。Agent 不是万能的，它需要预加载特定场景的操作规范。

Johnny 说了一个让我印象深刻的观点：**大模型并不具备自主操作资金的能力**。它可能知道 Uniswap 是什么，但具体怎么调用合约、怎么设置滑点、怎么处理异常，它并不擅长。Recipe 就是把这些"怎么做"打包成知识胶囊，让 Agent 按照已验证的路径执行，而不是随意发挥。

已上线的 Recipe：Aave V3、Uniswap V3、Polymarket、Hyperliquid。

（这让我想到昨天学的 Agent 记忆系统——记忆让 Agent 更聪明，Recipe 让 Agent 更准确。但两者都可能泄露，都需要安全边界。安全和能力永远是跷跷板的两端。）

#### Q&A 精华

讲座最后有 7 个问答，有几个特别有意思：

**小额免密支付**
有人问有没有考虑过小额免密支付。Johnny 说已经支持 x402 微支付协议和 gasless 场景。在 Pact 体系下，可以限制单次金额、转账地址、频次、总上限。超过上限需要临时单笔授权。

（这让我想到支付宝的免密支付——你设了 200 块以下免密，超过 200 要输密码。Pact 做的是同样的事，只不过是在链上。）

**Agent 支付一定要在链上吗？**
有人问了一个很尖锐的问题：大部分用户不在意去中心化，只是觉得方便就行。

Johnny 的回答很诚实：Web2 和 Crypto 各占一部分。链上是快速高效的结算系统，跨境支付已开始用 USDC/USDT。但短期不会完全颠覆 Web2。

（这个回答让我对 Agent 经济的未来有了更现实的认知——不是"链上取代一切"，而是"两者共存，Crypto 比重持续增长"。）

**Human-in-the-loop 的未来**
Johnny 说短期（1-2 年）Human-in-the-loop 不可或缺，因为 Agent 基础设施还不健全。但长期（5-10 年）可能出现 Agent 自发支付、Agent 雇佣 Agent 的场景。

（这个回答让我有点兴奋又有点担忧。兴奋的是 Agent 经济的想象空间很大；担忧的是如果 Agent 真的能自己做决策，我们人类的角色是什么？）

**Agent 掉线怎么办？**
有人问了极端情况。Johnny 说 MPC 做了冗余设计——Agent 私钥分片会 re-share 给移动端。只要 follow 安全规范，钱肯定不会丢。但 Agent 能力可能需要重新配置。

（这让我想到一个有趣的悖论：我们用 MPC 来防止单点故障，但 MPC 本身也需要备份和恢复机制。安全设计永远是在"防住坏人"和"不把自己锁外面"之间找平衡。）

讲座结束后，我读了 Handbook 里四个相关页面，发现它们刚好形成一条完整的知识链：

Chain-aware Context（看见）→ AI Agent（思考）→ Web3 Tool Use（行动）→ MCP（连接）→ Pact（约束）

这和 Cobo 的 Pact 设计完全一致。不是限制 Agent 的能力，而是给它一个明确的"工作说明书"。

我还发现了一个有趣的对照：

| 讲座概念 | Handbook 对应 | 关系 |
|---------|-------------|------|
| Pact（Intent/Plan/Policies） | Agent 的 Planning + State | Pact 是 Planning 在链上场景的具体实现 |

（我之前一直觉得 Handbook 里的内容和讲座是分开的，没想到它们其实在讲同一件事——只是角度不同。Handbook 讲"技术组件"，讲座讲"产品组装"。今天终于把它们串起来了。）

## 二、核心收获

1. **"Agent 管钱"的本质是权限管理问题**：不是让 Agent 更聪明，而是让它的每一步都在人类设定的边界内。这和金融风控的逻辑一模一样——你不会因为交易员能力强就给他无限额度。

2. **Pact 的设计思路很有启发**：Intent（你要做什么）→ Plan（怎么做）→ Policy（红线在哪）→ Complete（怎样算做完）。这不只是 Agent 的授权协议，其实也是我们日常给人授权的通用框架。下次你让朋友帮你办事，也可以想想这四个要素。

3. **"知识胶囊"是个好概念**：Agent 不是万能的，它需要预加载特定场景的操作规范。这让我想到昨天学的 Agent 记忆系统——记忆让 Agent 更聪明，Recipe 让 Agent 更准确，但两者都可能泄露，都需要安全边界。

4. **从"学概念"到"看产品"的视角升级**：之前学的 MCP、Tool Use、Chain-aware Context 都是"技术组件"，今天看到的是"把这些组件组装成产品"的完整思路。技术是零件，产品是机器。

5. **安全和能力永远是跷跷板的两端**：Agent 越自主越有用，但也越危险。Cobo 的 Pact 协议就是找到平衡点的工具——不是限制能力，而是框定边界。
