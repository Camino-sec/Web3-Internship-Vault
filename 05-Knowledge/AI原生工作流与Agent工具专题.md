# AI 原生工作流与 Agent 工具专题

> 来源：2026-06-03 学习打卡，三篇关于 AI 原生工作方式的内容整合

---

## 一、核心框架：什么是 AI 原生工作流？

**不是"用 AI 工具"，而是"用 AI 的逻辑重新设计整个工作方式"。**

过去所有软件工程流程（瀑布、敏捷）都在管理同一个成本——写代码太贵了。AI 时代这个前提变了，围绕它的所有流程都需要重新设计。

就像从马车到汽车，不只是换发动机，整个公路系统、交通规则、城市规划都得重来。

---

## 二、Claude Code 团队的 5 条新规范

### 1. JIT 规划（Just-In-Time Planning）
- **旧**：写长篇设计文档 → 开会评审 → 再编码
- **新**：原型先行，代码赢才牛逼
- 有分歧？让 Claude 把两个方案都做成原型，看实物聊
- *"Building is cheap, arguing is expensive."*

### 2. 自动化肌肉记忆
- 重复 3 次以上的事情就自动化
- 自动化成本已经几乎为零，逻辑反过来了
- 从今天开始，找一件重复做的事，花十分钟自动化掉
- 触发器 hook 是非常好用的自动化模式

### 3. Trust but Verify（信任但验证）
- Claude 处理：风格检查、linting、PR 反馈、bug 捕捉、补充测试（约 60-70% 的 review 工作量）
- 人类聚焦：法律合规、安全敏感代码、产品方向和品味判断
- 这条线是动态的——今天需要人做的，下一个模型可能就能做了

### 4. 角色边界模糊化
- PM 在大量写代码，工程师也在做内容和设计
- *"Taste is scarce, typing is not."* —— 品味是稀缺的，打字不是
- 招人看两种特质：有产品 sense 的创意 builder + 有深厚系统背景的工程师
- 不在乎你一小时写多少行代码，在乎你选择去做什么，以及怎么知道它是对的

### 5. 主动清理旧流程
- 人不会主动删除流程，只会在旧流程上叠新流程
- 需要有人站出来说"这个会还需要吗"
- 定期审视：*"Pick your noisiest workflow. Ask if it still earns its place."*

## 三、浏览器自动化：BrowserAct

### 解决的问题
Playwright 等基础框架对真实互联网场景没有专门优化：
- 扫码登录、Session 保持
- 机器人验证弹窗
- 反爬虫检测
- 多账号隔离

### 两个核心 Skill
1. **browser-act CLI**：实时浏览器控制，一次性任务
2. **browser-act-skill-forge**：把网站操作封装成可复用的 Skill，踩坑经验自动沉淀

### 三种浏览器模式
| 模式 | 用途 | 特点 |
|------|------|------|
| Stealth | 突破反爬 | 反检测指纹 + 动态代理 + 验证码自动解决 |
| Chrome | 复用登录态 | 加载已有 Cookie，免重新认证 |
| Chrome-Direct | 人机协同 | 直连当前浏览器，零配置 |

### 核心价值
AI Agent 要在真实互联网里稳定工作，需要专门的"最后一公里"基础设施。Stealth 浏览器帮 Agent 适应真实环境的复杂性。

## 四、额度管理：5 小时滚动窗口技巧

### 原理
- Codex/Claude Code 额度是 5 小时滚动窗口
- 从发第一条消息开始计时
- 窗口结束后不会自动重置，等发下一条消息才重新开始

### 技巧
提前 3 小时发一条消息激活窗口，让重置时间落在核心工作时段中间：

```
11:00 发消息 → 窗口开始
14:00 开始干活 → 已过 3 小时
16:00 窗口重置 → 新窗口开启
18:00 下班 → 核心时段享受两个窗口
```

### 自动化
- Codex：设置自动化，触发条件选"每天"，时间填干活前 3 小时
- Claude Code CLI：crontab 定时任务
- 注意：周额度上限仍然存在，合理分配

## 五、底层逻辑总结

三篇内容的共同主题：**理解系统规则，然后重新设计工作方式。**

1. 理解 AI 让"做事"变便宜 → 砍掉围绕"做事贵"设计的冗余流程
2. 理解浏览器检测原理 → 帮 Agent 克服真实环境的障碍
3. 理解额度窗口重置机制 → 让系统为你服务

**认知升级永远先于工具升级。**
