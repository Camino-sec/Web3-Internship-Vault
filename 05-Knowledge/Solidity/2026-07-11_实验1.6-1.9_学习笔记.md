## 🔬 实验 1.6 整型溢出

### 📖 实验背景

> 《道德经》第三十六章："将欲歙(xi)之，必固张之；将欲弱之，必固强之；将欲废之，必固兴之；将欲取之，比固与之。"

Solidity 的整型向上溢出就是这样的道理——你要想其失效，就得先给予它想要的，等它膨胀到超出其能够承受的范围，它就会开始失常了。

**历史案例**：黑客对 BEC 智能合约化用过这样的技巧，使得一些合约发行的币一夜归零。

### 🎯 实验目的

1. 了解 Solidity 中的整型溢出
2. 学会处理 Solidity 中整型溢出问题

### 📝 实验代码

```solidity
// SPDX-License-Identifier: GPL-3.0
pragma solidity ^0.6.0;

contract demo {
    // 函数 add 将会返回什么值？（1）
    function add() public pure returns (uint8 _overflow) {
        uint8 max = 256 - 1;  // uint8 最大值是 255
        return max + 1;       // 255 + 1 = ?
    }
    
    // 函数 sub 将会返回什么值？（2）
    function sub() public pure returns (uint8 _underflow) {
        uint8 min = 0;        // uint8 最小值是 0
        return min - 1;       // 0 - 1 = ?
    }
    
    // 函数 mul 将会返回什么值？（3）
    function mul_overflow() public pure returns (uint8 _overflow) {
        uint8 mul = 128;
        return mul * 2;       // 128 * 2 = ?
    }
}
```

### 💡 答案分析

#### 问题 1：`add()` 返回什么？

**答案**：`0`

**原理**：
- `uint8` 的范围是 0-255（2^8 - 1）
- 255 + 1 = 256，但 256 超出了 `uint8` 的范围
- 在 Solidity 0.6.0 中，会发生**溢出**，256 变成 0（回到起点）

**生活类比**：就像汽车里程表，999999 + 1 = 000000（回到起点）

#### 问题 2：`sub()` 返回什么？

**答案**：`255`

**原理**：
- 0 - 1 = -1，但 `uint8` 是无符号整数，不能表示负数
- 发生**下溢**，-1 变成 255（最大值）

**生活类比**：就像倒退的里程表，000000 - 1 = 999999

#### 问题 3：`mul_overflow()` 返回什么？

**答案**：`0`

**原理**：
- 128 * 2 = 256，超出了 `uint8` 的范围
- 256 溢出后变成 0

### 🛡️ 安全防护方案

#### Solidity 0.8.0+ 的内置保护

从 Solidity 0.8.0 开始，编译器会自动检查溢出，溢出会直接报错（revert）。

```solidity
// SPDX-License-Identifier: GPL-3.0
pragma solidity ^0.8.0;  // 使用 0.8.0+

contract SafeDemo {
    function safeAdd() public pure returns (uint8) {
        uint8 max = 255;
        return max + 1;  // 编译时会报错！
    }
}
```

#### 使用 OpenZeppelin 的 SafeMath（适用于 0.8.0 以下版本）

```solidity
// SPDX-License-Identifier: GPL-3.0
pragma solidity ^0.6.0;

import "@openzeppelin/contracts/math/SafeMath.sol";

contract SafeMathDemo {
    using SafeMath for uint8;
    
    function safeAdd() public pure returns (uint8) {
        uint8 max = 255;
        return max.add(1);  // 安全！会 revert
    }
}
```

### 🔑 核心知识点

1. **溢出（Overflow）**：数值超过类型最大值，回到最小值
2. **下溢（Underflow）**：数值低于类型最小值，回到最大值
3. **Solidity 0.8.0+**：内置溢出保护，溢出会 revert
4. **SafeMath**：适用于 0.8.0 以下版本的安全数学库

## 🔬 实验 1.7 整形字面量

### 📖 实验背景

> 《道德经》第七十七章："天之道，损有余而补不足；人之道则不然，损不足以奉有余。"

Solidity 中的运算像是"天道"，默默地为有限的存储空间计算着超越其本身能够存储的数字的运算。

### 🎯 实验目的

通过与其他编程语言之间的运算结果对比，来理解 Solidity 函数对运算数字的范围与类型是否有要求。

### 📝 实验代码

```solidity
// SPDX-License-Identifier: GPL-3.0
pragma solidity ^0.8.0;

contract HelloWorld {
    // 实验1：哪些函数将编译失败？
    
    // 函数1：直接使用大数字
    function test1() public pure returns (uint8) {
        return 256;  // 编译失败？还是成功？
    }
    
    // 函数2：使用十六进制
    function test2() public pure returns (uint8) {
        return 0x100;  // 编译失败？还是成功？
    }
    
    // 函数3：使用科学计数法
    function test3() public pure returns (uint8) {
        return 2.56e2;  // 编译失败？还是成功？
    }
    
    // 函数4：使用下划线分隔
    function test4() public pure returns (uint8) {
        return 1_000;  // 编译失败？还是成功？
    }
}
```

### 💡 答案分析

#### 函数 1：`test1()`
**答案**：编译失败 ❌

**原因**：
- `256` 超出了 `uint8` 的范围（0-255）
- 编译器会直接报错

#### 函数 2：`test2()`
**答案**：编译失败 ❌

**原因**：
- `0x100` = 256（十六进制转十进制）
- 同样超出了 `uint8` 的范围

#### 函数 3：`test3()`
**答案**：编译失败 ❌

**原因**：
- `2.56e2` = 256（科学计数法）
- 同样超出了 `uint8` 的范围

#### 函数 4：`test4()`
**答案**：编译失败 ❌

**原因**：
- `1_000` = 1000（下划线只是视觉分隔符）
- 超出了 `uint8` 的范围

### 🔑 核心知识点

1. **字面量类型**：代码中直接写死的数字
2. **编译时检查**：Solidity 编译器会检查字面量是否超出目标类型范围
3. **不同表示法**：十进制、十六进制、科学计数法、下划线分隔，本质相同
4. **安全第一**：编译时就报错，比运行时溢出更安全

### 🆚 与其他语言的对比

```java
// Java 代码
public class Test {
    public static void main(String[] args) {
        byte b = 256;  // 编译失败：不兼容的类型
    }
}
```

**结论**：Solidity 和 Java 都会在编译时检查字面量是否超出目标类型范围。

## 🔬 实验 1.9 动态字节数组

### 📖 实验背景

> 王籍在《入若耶溪》写道："禅噪林逾静，鸟鸣山更幽。"

动静结合，像是哲学里的矛盾关系一样。而在 Solidity 里，动态字节数组也显现出它独有的魅力。

### 🎯 实验目的

1. 学会创建一个动态数组，并去获取它的元素
2. 了解对动态数组的修改，获取它的动态长度，并学到动态数组里的 push 方法

### 📝 实验代码

```solidity
// SPDX-License-Identifier: GPL-3.0
pragma solidity ^0.8.0;

contract DynamicByte {
    bytes public name = new bytes(2);
    
    // 初始化 name
    function Initname() public {
        name[0] = 0x11;
        name[1] = 0x22;
    }
    
    // 将 bytes 转换为 string
    function bytesToString() public view returns (string memory) {
        // 补充代码：将 bytes 类型的 name 转换为 string 类型并返回
        return string(name);
    }
    
    // 追加一个字节
    function pushBytes() public {
        // 补充代码：使用 push 关键字对动态字节 name 追加一个字节（如：0x99）
        name.push(0x99);
    }
    
    // 修改指定位置的字节
    function changename() public {
        // 补充代码：将 name 字节索引 0 处的字符改为 0x88
        name[0] = 0x88;
    }
    
    // 获取 name 的长度
    function getLength() public view returns (uint256) {
        return name.length;
    }
    
    // 获取指定位置的字节
    function getByte(uint256 index) public view returns (byte) {
        return name[index];
    }
}
```

### 💡 代码解析

#### 1. 初始化 `Initname()`
```solidity
function Initname() public {
    name[0] = 0x11;
    name[1] = 0x22;
}
```
- 设置数组的两个元素
- 索引从 0 开始

#### 2. 转换为字符串 `bytesToString()`
```solidity
function bytesToString() public view returns (string memory) {
    return string(name);
}
```
- `bytes` 类型可以直接转换为 `string`
- 使用 `string()` 构造函数

#### 3. 追加字节 `pushBytes()`
```solidity
function pushBytes() public {
    name.push(0x99);
}
```
- `push()` 方法会将新字节追加到数组末尾
- 数组长度自动 +1

#### 4. 修改字节 `changename()`
```solidity
function changename() public {
    name[0] = 0x88;
}
```
- 直接通过索引修改元素
- 会覆盖原有值

### 🔑 核心知识点

1. **动态数组**：长度可变的数组，使用 `bytes` 类型
2. **push 方法**：向数组末尾追加元素
3. **length 属性**：获取数组当前长度
4. **索引访问**：通过 `name[index]` 访问或修改元素

### 🆚 固定长度 vs 动态长度

| 特性 | 固定长度 `bytes1`-`bytes32` | 动态长度 `bytes` |
|------|---------------------------|-----------------|
| 长度 | 编译时确定，不可变 | 运行时可变 |
| 存储 | 更省 Gas | 需要额外存储 |
| 操作 | 不能 push/pop | 可以 push/pop |
| 使用场景 | 固定长度数据（如地址） | 可变长度数据（如字符串） |
