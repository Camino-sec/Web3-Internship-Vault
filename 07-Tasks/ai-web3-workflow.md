## 关键边界标注

### 谁发起任务？
- **用户发起**：告诉 AI 想做什么操作

### 谁执行？
| 步骤 | 执行者 | 说明 |
|------|--------|------|
| 规划、解释、检查 | AI / Agent | 信息处理，不涉及资产 |
| 生成交易摘要 | AI / Agent | 只是草稿，不是交易 |
| 提供操作指引 | AI / Agent | 教学性质 |
| **签名确认** | **用户** | 🔴 必须人工，AI 无法参与 |
| **链上执行** | **区块链网络** | 验证者打包，去中心化 |
| 查询验证 | AI / Agent | 只读操作 |
| **结果确认** | **用户** | 人工验证 |

### 哪一步需要钱包签名 / 付款 / 授权？
- **只有一步**：人工确认点 #2（MetaMask 签名）
- 这一步完全由用户在 MetaMask 中完成
- AI 无法接触私钥，无法替用户签名

### 哪一步必须人工确认？
1. **审查交易摘要**：确认地址、金额、网络
2. **MetaMask 签名**：确认交易详情，点击"确认"
3. **验证交易成功**：在 Etherscan 确认结果

### 如何验证结果？
1. **交易哈希**：每笔交易的唯一标识
2. **区块浏览器**：Etherscan 查看交易状态
3. **交易状态**：Success / Failed
4. **确认数**：区块确认次数（越多越安全）

### 可能的风险点

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| **AI 幻觉** | AI 可能给出错误的 Gas 预估或地址信息 | 所有 AI 输出需人工交叉验证 |
| **地址归属** | AI 只能检查格式，不能检查"给谁" | 用户需从可信来源复制地址 |
| **过度信任** | 用户可能跳过确认 | Workflow 强制插入人工确认点 |
| **钓鱼攻击** | 用户被诱导到恶意网站 | AI 提醒只在可信平台交互 |
| **私钥泄露** | 用户在不安全环境输入私钥 | AI 永远不接触私钥 |

## 流程图说明（3-5 句话）

### 1. 这个流程解决什么问题？
帮助 Web3 新手安全完成测试网交易——AI 负责规划、解释、检查，用户负责签名、确认、验证，确保每一步都可控、可验证。

### 2. 哪些步骤由 AI / Agent 辅助？
- 解释交易含义、检查地址格式、预估 Gas 费
- 生成交易摘要（草稿）
- 提供操作指引
- 查询交易结果、生成学习记录

### 3. 哪些步骤必须人工确认？
- 审查交易摘要（确认地址、金额、网络）
- MetaMask 签名（确认交易详情）
- 验证交易成功（在 Etherscan 确认结果）

### 4. 如何验证最终结果？
通过 Etherscan 查看交易哈希、交易状态（Success/Failed）、区块号、确认数，确保交易按预期执行。

### 5. 主要风险点是什么？
- AI 幻觉导致错误信息（需人工验证）
- 地址归属无法确认（用户需自行验证）
- 用户过度信任 AI 而跳过确认（强制人工确认点）
- 钓鱼攻击（只在可信平台交互）
- 私钥泄露（AI 永远不接触私钥）

## 核心原则

```
AI 是参谋，不是司机
├── AI 规划、解释、检查
├── 人类决策、确认、执行
└── 私钥和助记词是不可触碰的红线
```

## 实际应用

这个 Workflow 就是我完成 Sepolia 转账和合约部署时的真实流程：

1. **告诉 Hermes**：想转 0.01 ETH / 想部署合约
2. **Hermes 帮我**：解释交易、检查地址、预估 Gas、生成操作指引
3. **我在 MetaMask 里**：手动操作、确认交易详情、点击签名
4. **Hermes 帮我查**：用 Etherscan 验证交易状态
5. **我确认**：交易成功，记录交易哈希

**Hermes 没有碰过我的私钥，没有替我签名，所有关键操作都是我自己完成的。**
