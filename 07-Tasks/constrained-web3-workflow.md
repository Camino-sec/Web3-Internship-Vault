# 🔒 受限 Web3 助手：测试网交易引导 Workflow

> AI × Web3 School Week 1 · Luvia
> 设计一个"受限"的 AI Web3 助手——AI 能帮忙规划、解释、检查，但不能碰私钥、不能绕过人工确认。

---

## 一、这个助手要解决什么问题？

**痛点**：Web3 新手第一次在测试网转账时，面对 MetaMask 弹窗、Gas 设置、地址格式、交易确认等一系列陌生操作，很容易：
- 转错地址（复制不完整或多了空格）
- Gas 设置不合理（太低导致交易卡住）
- 不知道交易是否成功（不会查区块浏览器）
- 被钓鱼网站诱导签名恶意交易

**解决方案**：设计一个 AI 辅助的交易引导 Workflow，让 AI 帮你做"准备和检查"，但最终的签名和发送由你自己在 MetaMask 里完成。

**核心原则**：AI 是"参谋"，不是"司机"——它帮你规划路线、检查路况，但方向盘永远在你手里。

## 三、输入和输出示例

### 输入示例

用户对 AI 说：
> "我想从我的测试钱包 0x7F1a...524DB 转 0.01 ETH 到 0x6fD7...a968，在 Sepolia 测试网上。我该怎么做？"

### 输出示例

AI 回复：

> **交易摘要（草稿）**
> - 发送方：`0x7F1a8ddbdECCA0945c392297e97CFe4694A524DB`
> - 接收方：`0x6fD78Be313597511Cb034100Db13499D6c41a968`
> - 金额：0.01 ETH
> - 网络：Sepolia 测试网
> - 预估 Gas：~0.0001 ETH
>
> ⚠️ **请确认**：这个接收地址是你想转的人吗？AI 无法验证地址归属。
>
> **操作步骤**：
> 1. 打开 MetaMask，切换到 Sepolia 网络
> 2. 点击"发送"
> 3. 粘贴接收地址（建议从区块浏览器复制，不要手动输入）
> 4. 输入金额 0.01
> 5. 检查 Gas 费是否合理
> 6. 点击"确认"
>
> **签名后**，我会帮你查询交易状态。

## 四、AI 能做什么 vs 不能做什么

### ✅ AI 可以做的（规划、解释、检查、记录）

| 步骤 | AI 做什么 | 为什么安全 |
|------|----------|-----------|
| 解释交易含义 | 告诉用户这笔交易在做什么 | 只是信息输出，不涉及资产 |
| 检查地址格式 | 验证地址是否是合法的 42 位十六进制 | 不涉及私钥 |
| 预估 Gas 费 | 查询当前网络 Gas 价格 | 只读操作，不涉及签名 |
| 生成交易摘要 | 整理交易参数供用户确认 | 只是草稿，不是交易本身 |
| 提供操作指引 | 告诉用户在 MetaMask 里怎么操作 | 教学性质，不执行任何操作 |
| 查询交易结果 | 调用 Etherscan API 查交易状态 | 只读操作，不涉及资产 |
| 生成学习记录 | 整理交易信息保存到笔记 | 记录性质，不涉及资产 |

### 🔴 AI 不能做的（签名、授权、转账、接触密钥）

| 步骤 | 为什么不能 | 后果 |
|------|-----------|------|
| 访问私钥 | 私钥是账户控制权，泄露 = 归零 | AI 没有、也不应该有私钥访问权限 |
| 访问助记词 | 助记词能推导所有私钥 | 同上 |
| 替用户签名 | 签名 = 授权，不可逆 | 如果 AI 能签名，就能转走所有资产 |
| 自动发起交易 | 绕过人工确认 = 失去最后防线 | 代码 bug 或 AI 幻觉可能导致错误交易 |
| 修改授权额度 | 授权 = 给合约花钱的权限 | 恶意合约可能利用授权转走资产 |
| 自动处理错误 | AI 可能"自作主张"修复问题 | 可能导致更大的问题 |

## 五、风险和限制

### 风险 1：AI 幻觉导致错误信息
- **场景**：AI 可能给出错误的 Gas 预估，或者"看到"一个不存在的交易状态
- **缓解**：所有 AI 输出都需人工交叉验证——去 Etherscan 自己查
- **本质**：AI 的信息来自训练数据和 API 调用，可能过时或不准确

### 风险 2：地址归属无法验证
- **场景**：用户说"转给小明"，AI 无法验证 `0x6fD7...a968` 是否真的属于小明
- **缓解**：AI 会提醒用户自行确认地址归属，建议从可信来源复制地址
- **本质**：AI 只能检查地址"格式"是否正确，不能检查"归属"是否正确

### 风险 3：用户过度信任 AI 而跳过确认
- **场景**：用户觉得"AI 说没问题就没问题"，不仔细看 MetaMask 弹窗就点确认
- **缓解**：Workflow 设计中强制插入人工确认点，AI 在每个关键步骤前都会提醒
- **本质**：Human-in-the-Loop 的价值在于人真的会看，而不是走形式

### 风险 4：AI 无法处理链上异常
- **场景**：交易卡住（Gas 太低）、合约调用失败、链上回滚等
- **缓解**：AI 可以解释可能的原因和解决方案，但最终操作还是由用户执行
- **本质**：AI 不是区块链节点，无法直接影响链上状态

### 风险 5：钓鱼攻击
- **场景**：用户被钓鱼网站诱导，以为在和 AI 交互，实际上在和骗子交互
- **缓解**：AI 会提醒用户只在可信平台（如 Hermes Agent）交互，不要在陌生网站输入任何信息
- **本质**：AI 本身也可能是被冒充的，用户需要验证交互平台的可信度

## 六、如何验证执行结果

| 验证步骤 | 方法 | 谁来做 |
|----------|------|--------|
| 交易是否成功 | 在 Etherscan 输入交易哈希，查看 Status 字段 | 用户 + AI 协助 |
| 接收地址是否正确 | 对比交易摘要和 Etherscan 显示的接收地址 | 用户确认 |
| 金额是否正确 | 对比交易摘要和 Etherscan 显示的金额 | 用户确认 |
| Gas 费是否合理 | 对比预估和实际 Gas 费用 | AI 分析 + 用户确认 |
| 区块确认数 | Etherscan 显示的 Confirmations 数量 | AI 查询 + 用户确认 |

**验证原则**：AI 可以帮你查，但你要自己看。就像会计帮你做账，但老板要自己签字。

## 七、Workflow 设计原则总结

```
┌─────────────────────────────────────────────────────────────┐
│                    设计原则                                   │
├─────────────────────────────────────────────────────────────┤
│  1. AI 是参谋，不是司机                                       │
│     - AI 规划、解释、检查                                     │
│     - 人类决策、确认、执行                                     │
│                                                             │
│  2. 私钥和助记词是红线                                         │
│     - AI 永远不接触、不存储、不传输                            │
│     - 这是不可协商的安全底线                                   │
│                                                             │
│  3. 人工确认点不可跳过                                         │
│     - 每个关键步骤前都有确认提醒                               │
│     - 即使用户说"不用看了"，AI 也会坚持提醒                    │
│                                                             │
│  4. 透明的能与不能                                            │
│     - 明确告诉用户哪些 AI 能做、哪些不能                       │
│     - 不夸大 AI 能力，不隐瞒 AI 限制                          │
│                                                             │
│  5. 结果可验证                                                │
│     - 所有链上操作都能在区块浏览器验证                         │
│     - AI 提供查询帮助，但用户做最终判断                        │
└─────────────────────────────────────────────────────────────┘
```

## 八、实际应用：我的 Sepolia 转账经历

这个 Workflow 其实就是我这周完成 Sepolia 测试网转账时的真实流程：

1. **我告诉 Hermes**：想从账户 A 转 0.01 ETH 到账户 B
2. **Hermes 帮我**：解释交易含义、检查地址格式、预估 Gas
3. **我在 MetaMask 里**：手动操作、确认交易详情、点击签名
4. **Hermes 帮我查**：用 Etherscan 验证交易状态
5. **我确认**：交易成功，记录交易哈希

整个过程中，Hermes 没有碰过我的私钥，没有替我签名，所有关键操作都是我自己在 MetaMask 里完成的。这就是"受限"的含义——AI 能帮忙，但不能越界。
