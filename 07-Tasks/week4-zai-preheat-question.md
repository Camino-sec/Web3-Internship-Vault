# Z.AI 分享会｜会前问题

## 赞助方：Z.AI

## 问题

GLM-5.1 在处理「多步验证型」长程任务时，如何平衡「自主推理的自信度」和「外部工具验证的必要性」？

具体来说：我们的 EIV（Execution-Integrity Validator）项目中，Agent 需要完成一个典型的长程任务链——

```
接收用户意图 → 拆解为多步执行计划 → 逐步调用链上工具 
→ 每步生成执行证据（ERC-8004 attestation）→ 汇总验证 → 最终判定
```

在这个流程中，GLM-5.1 经常出现一个倾向：**在推理阶段就「过度自信」地下结论**，跳过工具验证环节，或者工具返回的结果和模型推理冲突时，坚持自己的推理而不回退。

## 背景 / 卡点

我们用 Agent Loop 跑通了 eiv-core 的核心逻辑（23/23 测试通过），但在实际长程任务中发现：

1. **推理捷径问题**：模型在第 3 步推理时，会「猜」第 5 步的结果，然后直接跳过第 4、5 步
2. **证据忽略问题**：当工具返回的证据和推理不一致时，模型倾向于忽略证据、坚持推理
3. **终止过早问题**：模型在完成 70% 的任务时就宣布「完成」，剩下的步骤被跳过

这些问题在「短程任务」中不明显（因为步骤少，模型能全部记住），但在「长程任务」中会累积放大。

## 希望分享会回答什么

1. GLM-5.1 的 Long-Horizon Task 能力，在架构层面是如何实现「持续执行不跑偏」的？有没有类似「检查点」或「证据门槛」的机制？
2. 对于需要「每步都必须有工具验证证据」的场景（如 EIV），推荐什么样的 prompt 工程策略或 harness 设计模式？
3. Z.AI 平台是否提供「强制工具调用」或「证据驱动推理」的 API 参数，让模型在没有工具返回结果之前不允许输出最终结论？
