# 🧠 AI 基础概念卡片

> AI × Web3 School Week 1 · Luvia
> 用生活类比帮助自己建立 AI 领域的共同语言

---

## 1. LLM（大语言模型）

**一句话**：LLM 就是一个读过海量文本的"超级接话王"——它不真正理解你说的话，但它见过太多类似的对话，所以能猜出一个最合理的下一句。

**例子**：你问 Claude "什么是比特币？"，它并不是真的"懂"比特币，而是基于训练时读过的无数篇关于比特币的文章，拼出一段最像"正确回答"的文字。就像一个从没炒过股的人，但读了一万本财经书，你问他股票知识他能说得头头是道。

**误区**：很多人以为 LLM 什么都懂、说的都对。其实它会"一本正经地胡说八道"（hallucination）。它给你的答案是"统计上最可能的"，不是"事实正确的"。所以关键信息一定要自己验证。

---

## 2. Prompt（提示词）

**一句话**：Prompt 就是你给 AI 下的"指令"——你说得越清楚，它回答得越好。

**例子**：就像你去餐厅点菜。你说"来点吃的"，服务员可能随便给你上；但你说"要一份不辣的番茄鸡蛋盖饭，米饭少一点"，结果就精准多了。Prompt 也是一样：说清楚你要什么、什么格式、什么风格，AI 才能给你满意的结果。

**误区**：以为 Prompt 只是"问问题"。其实好的 Prompt 可以设定角色、限定格式、给出示例、要求分步骤思考。Prompt 不只是提问，更像是在"编程"你和 AI 的对话。

---

## 3. Context Window（上下文窗口）

**一句话**：Context Window 就是 AI 的"短期记忆容量"——它一次能记住多少内容是有上限的。

**例子**：想象你在跟一个朋友聊微信。如果你们聊了 1000 条消息，他不可能全部记住——他只能记住最近的几十条。Context Window 就是这个"最近能记住的范围"。如果你把一整本书丢给 AI，超出窗口的部分它就"忘"了。

**误区**：以为 AI 能记住你之前说过的所有话。实际上每次对话都有 token（可以理解为字数）上限。Claude 大约能处理 200K token（大概一本中等厚度的书），但也不是无限的。所以长对话时，重要的信息要重复提醒或者写进文件里。

---

## 4. Workflow（工作流）

**一句话**：Workflow 就是把一个复杂任务拆成多个步骤，按顺序或条件自动执行。

**例子**：就像银行的贷款审批流程：提交申请 → 系统初审 → 人工复核 → 批准/拒绝 → 通知客户。每一步有明确的输入和输出，有规则决定下一步走哪条路。AI Workflow 也一样——比如"收到用户问题 → AI 搜索资料 → AI 生成摘要 → 人工确认 → 发送给用户"。

**误区**：以为 Workflow 就是"让 AI 一口气干完所有事"。好的 Workflow 会把任务拆小，每一步可检查、可修改。就像你不会让实习生一个人搞定整个项目，而是分阶段给他任务，每阶段检查一下。

---

## 5. Agent（智能体）

**一句话**：Agent 就是一个能自己决定"下一步做什么"的 AI——不只是回答问题，还能主动规划和执行任务。

**例子**：普通的 AI 像一个客服——你问一句，它答一句。Agent 更像一个私人助理——你说"帮我订明天去上海的高铁"，它会自己查车次、比较价格、帮你选座、甚至提醒你带身份证。它能自己判断需要调用什么工具、按什么顺序完成。

**我现在就在用 Agent**：Hermes Agent 就是我的学习助手。我告诉它"帮我整理今天的笔记"，它会自己查日历、读文件、生成摘要、推送到 GitHub，不需要我一步步指挥。

**误区**：以为 Agent 无所不能、完全自主。实际上 Agent 的能力取决于它能用的"工具"和你给的"指令"。没有好的 Prompt 和 Tool，Agent 就像一个没有手机、没有电脑的助理——很聪明但啥也干不了。而且 Agent 做的每一步都可能出错，所以重要操作还是需要人来确认。

---

## 6. Tool Use（工具调用）

**一句话**：Tool Use 就是让 AI 能"动手做事"——不只是说话，还能真正执行操作。

**例子**：AI 本身只能生成文字。但加上 Tool Use，它就能：搜索网页、读写文件、调用 API、发送消息、操作数据库。就像一个只会纸上谈兵的军师，突然有了手和脚，能真正去打仗了。

**我在用的例子**：Hermes Agent 能帮我调用 WCB API 查任务、用 GitHub CLI 推代码、读写 Obsidian 笔记——这些都是 Tool Use。它不是自己"知道"怎么做，而是我告诉它"你有这些工具可以用"，它根据需要选择调用。

**误区**：以为 AI 调用工具就像人用工具一样自然。其实 AI 调用工具是靠你提前"教"它的——你得告诉它有哪些工具、每个工具怎么用、什么时候该用。工具的描述写得不好，AI 就会用错或者不用。

---

## 7. AI Coding（AI 辅助编程）

**一句话**：AI Coding 就是让 AI 帮你写代码——它可以补全代码、解释代码、找 bug，但它不能替你思考"要解决什么问题"。

**例子**：就像你用 Excel 的公式自动计算，但你得先想清楚"我要算什么"、"数据在哪里"。AI Coding 也一样：你说"帮我写一个 Python 脚本读取 CSV 文件并按日期排序"，它能很快写出来，但"为什么要排序"、"排序后要做什么"还是你来决定。

**我在用的例子**：Claude Code 能帮我写脚本、调试错误。有一次我要解析 WCB API 的返回数据，我描述了需求，它直接写出了完整的 Python 脚本。但遇到 API 返回格式不对的时候，还是我自己发现并告诉它怎么改的。

**误区**：以为 AI 写的代码可以直接用、不需要检查。实际上 AI 写的代码可能有 bug、可能不安全、可能不符合你的具体场景。AI Coding 是"副驾驶"，你才是"驾驶员"——方向盘不能交给它。

---

## 8. Human-in-the-Loop（人机协作）

**一句话**：Human-in-the-Loop 就是在 AI 工作流程中设置"人工检查点"——关键决策由人来做，AI 负责执行和建议。

**例子**：就像自动驾驶汽车——大部分时候车自己开，但遇到复杂路况（比如施工路段、突发事故）会提醒驾驶员接管。AI 系统也一样：日常任务自动处理，但重要操作（比如花钱、发布内容、修改关键数据）必须经过人工确认。

**我在用的例子**：Hermes Agent 帮我生成学习笔记和打卡内容，但每一篇我都会自己看一遍、改一改再发布。特别是发到小红书的内容，AI 生成的语气可能太正式，我会改成自己的风格。这就是 Human-in-the-Loop——AI 做初稿，我做终审。

**误区**：以为加了人工审核就万无一失。问题是：人也会偷懒、也会信任 AI 而不仔细看。"Human-in-the-Loop"不是形式上有人在，而是这个人真的会认真审核。如果你只是点"确认"而不看内容，那跟没有 loop 一样。

---

## 附：概念之间的关系

这些概念不是孤立的，它们构成了一个完整的 AI 应用链路：

```
Prompt（你下指令）
  → LLM（AI 理解并生成）
    → Context Window（决定 AI 能记住多少）
      → Agent（AI 自主规划下一步）
        → Tool Use（AI 调用工具执行）
          → Workflow（多个步骤串起来）
            → Human-in-the-Loop（关键节点人工确认）
              → AI Coding（用代码实现这一切）
```

就像一条生产线：Prompt 是订单，LLM 是工人，Context Window 是工人的工作台大小，Agent 是工头，Tool 是工具箱，Workflow 是生产流程，Human-in-the-Loop 是质检员。
