# DevRel 与 Ops 的区别

## 一句话定义

- **DevRel（Developer Relations，开发者关系）**：连接公司与外部开发者社区的桥梁，关注**人与社区**
- **Ops（Operations，运维/运营）**：确保系统稳定、安全、高效运行，关注**系统与基础设施**

## 生活类比

> DevRel 像一家餐厅的**品牌大使**——他不进厨房做菜，但他会去美食节推广餐厅、收集食客反馈、写菜谱教程，让更多人知道并爱上这家餐厅。
>
> Ops 像餐厅的**后厨总管**——他确保厨房设备正常运转、食材供应稳定、出餐流程高效、突发状况能快速处理。

## 核心对比

| 维度 | DevRel（开发者关系） | Ops（运维/DevOps） |
|------|---------------------|-------------------|
| **定位** | 对部开发者社区的桥梁 | 内部系统稳定运行的守护者 |
| **工作重心** | 开发者体验（DX） | 系统稳定性与交付效率 |
| **主要受众** | 外部开发者、开源社区 | 内部开发团队、业务系统 |
| **核心指标** | 社区活跃度、开发者 NPS、API 调用量 | 系统可用性（99.9%）、MTTR、部署频率 |

## 日常任务对比

### DevRel 的日常

- ✍️ 编写技术博客、教程和示例代码
- 🎤 在技术会议上发表演讲（技术布道）
- 💬 维护开发者社区（Discord、Slack、GitHub Issues）
- 🏁 组织黑客松、Meetup 等活动
- 📖 编写和优化 API 文档

### Ops 的日常

- 🔄 建立和维护 CI/CD 自动化部署管道
- ☁️ 管理云基础设施（AWS、Azure、Kubernetes）
- 📊 配置监控、日志和告警系统（Prometheus、Grafana）
- 🛡️ 制定灾难恢复计划与安全防护
- 🔧 生产环境故障排查与性能调优

## 技能要求对比

### DevRel 的能力模型（技术 + 沟通）

| 技能 | 说明 |
|------|------|
| 编程与技术理解力 | 写得出高质量示例代码，理解开发者痛点 |
| 沟通与表达能力 | 擅长写作（文档、博客）和公开演讲 |
| 同理心与社交能力 | 倾听开发者抱怨，社区中保持耐心和热情 |

### Ops 的能力模型（系统 + 自动化）

| 技能 | 说明 |
|------|------|
| 基础设施即代码（IaC） | 熟练使用 Terraform、Ansible 等工具 |
| 容器与编排 | 深入掌握 Docker、Kubernetes |
| 网络与安全 | 理解网络协议、负载均衡、防火墙及安全策略 |
| 脚本与自动化 | 擅长 Shell、Python、Go 编写自动化运维脚本 |

## 两者的交集

虽然职责不同，但在某些场景下会产生紧密交集：

### 场景 1：DevRel 服务于 Ops 产品

如果公司卖的是运维工具（如 Datadog）或云原生基础设施（如 HashiCorp），那么 DevRel 面对的受众正是 Ops 工程师。此时 DevRel 需要极深的 Ops 背景。

### 场景 2：平台工程（Platform Engineering）

Ops 团队有时会采用"DevRel 的思维"对待内部开发人员——把内部开发平台（IDP）当"产品"，把内部开发者当"客户"，通过提升"内部开发者体验（Internal DX）"减少摩擦。

## 和 AI × Web3 的关系

| 方向 | DevRel 的角色 | Ops 的角色 |
|------|--------------|-----------|
| AI Agent 平台 | 写 Agent 开发教程、办黑客松 | 部署和维护 Agent 基础设施 |
| Web3 协议 | 技术布道、维护开发者社区 | 运行节点、监控链上性能 |
| 开发者工具 | 写 SDK 文档、收集反馈 | 搭建 CI/CD、自动化测试 |
