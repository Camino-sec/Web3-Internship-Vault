### 二、产品 Pivot：从"社区头衔"到"Agent 配额"

**旧项目的问题**：
- 头衔 = 身份资产 → 持有者不愿意被强制买断
- 税金变成纯成本，没有对应回报
- 价值来自"稀缺性叙事"而非"使用量"

**Pivot 后**：
- 配额 = 算力调度权 = 生产资料
- 持有者每天在消耗它（调用 API）
- 哈伯格税可以发现真实价格 ✅

**核心教训**：机制设计的第一步不是写代码，而是想清楚"标的物的本质是什么"。

## 🧠 今天学到的最重要的 3 件事

### 1. 哈伯格税只适合"生产资料"

```
身份资产（头衔/徽章）→ 情感价值 > 市场价格 → 哈伯格税失效 ❌
生产资料（算力/API）→ 使用价值 = 市场价格 → 哈伯格税有效 ✅
```

### 2. 防 MEV 的关键不是"禁止"，而是"增加时间窗口"

荷兰拍衰减：价格从自报价线性衰减到地板价，给所有人公平的反应窗口。

### 3. 存储优化按"写入模式"分组

```
Slot 0: price + lastSettle  ← setPrice() 写这个
Slot 1: escrow + forecStart ← deposit() 写这个
```

不是"越紧凑越好"，而是"让每次操作只写 1 个 slot"。

## 🐛 踩坑记录

### 1. Solidity 解构赋值不支持内联类型声明

```solidity
// ❌ 编译错误
(price, escrow, uint32 lastSettle) = _getQuota(tokenId);

// ✅ 正确
uint32 lastSettle;
(price, escrow, lastSettle) = _getQuota(tokenId);
```

### 2. forecStart 的 uint16 溢出

用 uint16 存储相对偏移（最大 18 小时），在 366 天后触发违约时溢出。修复：改用 uint32 绝对时间戳。

### 3. foreclosed() 视图函数依赖状态副作用

需要先触发 setPrice 才能检测违约。修复：改为纯视图函数，直接比较 `escrow < owed`。
