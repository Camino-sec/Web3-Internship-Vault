## 🎯 核心收获

### 1. Solidity 基础语法（实验 1.6-1.9）

#### 整型溢出 — 安全防护思维 🟢

这是今天最有价值的安全知识：

- **溢出（Overflow）**：数值超过类型最大值，回到最小值（如 255 + 1 = 0）
- **下溢（Underflow）**：数值低于类型最小值，回到最大值（如 0 - 1 = 255）
- **历史案例**：BEC 智能合约因溢出漏洞被攻击，币值一夜归零
- **防护方案**：Solidity 0.8.0+ 内置溢出保护，溢出会直接 revert

生活类比：就像汽车里程表，999999 + 1 = 000000（回到起点）

#### 整形字面量 — 编译时安全 🟢

理解了 Solidity 的"安全第一"设计：

- 编译器会检查字面量是否超出目标类型范围
- 不同表示法（十进制、十六进制、科学计数法）本质相同
- 与 Java 等语言类似，编译时检查比运行时更安全

#### 动态字节数组 — 灵活存储 🟡

掌握了动态数组的基本操作：

- `bytes` 类型支持 `push()` 方法追加元素
- `length` 属性获取当前长度
- 通过索引访问和修改元素
- 比固定长度数组更灵活，但更费 Gas

### 2. Harberger Tax NFT — AI+人工的安全协作模式

今天最让我有收获的是复盘了安全修复的**完整流程**：

```
AI 审查（Claude）发现零押金窗口问题
    ↓
人工读代码交叉验证
    ↓
判断严重性：Monad 出块极快，这是真实可利用的漏洞
    ↓
设计修复方案：改函数签名（breaking change）
    ↓
实现：buyout(price, depositAmount) 原子操作
    ↓
回归测试验证
```

**关键判断**：
- 选择改签名而不是仅文档提醒 → **安全问题不能靠"小心点"解决**
- depositAmount 可以为 0 → **把选择权交给用户，不要强制**
- 加 nonReentrant → **纵深防御，即使当前逻辑安全也要加**

这个流程本身就是一份很好的"AI 辅助开发"案例——**AI 能发现问题，但严重性判断和修复决策是人做的**。
