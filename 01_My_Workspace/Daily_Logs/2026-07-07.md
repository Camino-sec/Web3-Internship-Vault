| 学到的新概念 (双链到 02-Concepts) | 状态 (🟢/🟡/🔴) | 费曼大白话解释 (用2句话跟外行解释清楚) |
| :--- | :---: | :--- |
| [[智能合约部署流程]] | 🟢 | 智能合约部署就像在区块链上"注册一个公司"。交易 hash 是你的"注册申请回执"，合约地址是你的"营业执照号"。MetaMask 是帮你签字的"公证人"，但真正的"工商局"是全网的矿工/验证者。 |
| [[合约地址vs交易地址]] | 🟢 | 部署合约会产生一个交易 hash（66 字符），同时生成一个合约地址（42 字符）。交易 hash = "我做了一件事"（部署合约），合约地址 = "这个合约在哪里"（链上的位置）。 |
| [[Write vs Read函数]] | 🟢 | `set(42)` 需要签名 + Gas，`get()` 直接调用就行。这就像——写入是寄快递（要邮费），读取是查快递单号（免费）。这种设计约束其实是在保护网络资源。 |
| [[MetaMask签名机制]] | 🟢 | MetaMask 只负责帮你签名确认，真正的执行是矿工/验证者做的。签名完了还要等区块确认。这让我理解了区块链的去中心化本质——没有单一的服务器在执行，而是全网共识。 |
| [[RPC查询验证]] | 🟡 | 区块浏览器有时候显示不全（比如合约地址被截断），所以用 Monad Testnet RPC 直接查询了交易详情。这种方式拿到的数据比浏览器更完整，也让我理解了"链上数据是公开可查的"的真正含义。 |
| [[合约地址+ABI]] | 🟢 | 合约地址就像房子的门牌号（比如 `0x321...79c1F`），ABI 就像这栋房子的钥匙（Application Binary Interface，应用二进制接口）。ABI 本质上是一份「接口说明书」，告诉外部程序：这个合约有哪些函数、每个函数需要什么参数、返回什么值。 |
| [[Monad高频场景分析]] | 🟢 | 我选了「链上实时排行榜 + 任务系统」这个场景。选它的原因是：作为运营，我太清楚社区积分系统的痛点了——Galxe 的积分是黑箱，管理员可以随时改数据，用户没有所有权。如果能把排行榜放到链上，每次任务完成时实时更新，这不只是技术升级，更是信任升级。 |
| [[以太坊客户端架构]] | 🟡 | 以太坊不只是一条链，它是一整个「交通系统」——有人造车（客户端团队），有人修路（协议改进），有人设计红绿灯（共识机制）。EPF 就是高速公路管理局的实习生项目，入选者参与设计和改进公路本身，而不是在公路上开车。 |
| [[EPF项目理解]] | 🔴 | EPF 是以太坊基金会的协议层研究奖学金，入选者会参与以太坊核心开发。里面的项目分为几类：造新车（客户端开发）、改装车辆（协议改进）、设计未来交通系统（前沿研究）。我特别关注了「后量子安全」这个方向。 |
