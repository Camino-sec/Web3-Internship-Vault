## 📚 【下班前：3分钟】新知沉淀与红绿灯自评 (Evening Feynman)
> 💡 *放轻松！如果今天太累了，只写"红绿灯"就行；状态好，就多写两句费曼。*

| 学到的新概念 (双链到 02-Concepts) | 状态 (🟢/🟡/🔴) | 费曼大白话解释 (用2句话跟外行解释清楚) |
| :--- | :---: | :--- |
| [[Solidity值类型vs引用类型]] | 🟢 | 值类型（uint、bool、address）直接存值，赋值就是复制；引用类型（string、array、mapping）存的是指针，赋值可能只是共享同一个引用。就像——值类型是「拍照」，你有一张独立的照片；引用类型是「共享相册」，大家都指向同一个地方。 |
| [[函数修饰符]] | 🟢 | pure 不读不写、view 只读不写、external 只能外部调用、public 内外都能调。记忆技巧：pure 是「闭着眼睛算」，view 是「只看不摸」，external 是「只接外卖单」，public 是「堂食外卖都行」。 |
| [[memory vs storage vs calldata]] | 🟡 | storage 存在链上（贵，但永久）、memory 是临时的（函数结束就消失）、calldata 是只读的外部参数。判断流程：函数参数用 calldata（只读）或 memory（需要修改）；局部变量用 memory；状态变量自动是 storage。 |
| [[合约继承与接口]] | 🟢 | 用 `is` 继承，用 `override` 覆写，用 `virtual` 允许被覆写。接口（interface）只有函数签名，没有实现，用来调用别人的合约——就像「插座标准」，只要接口对得上，任何合约都能接进来。 |
| [[Agent支付核心问题]] | 🟢 | AI Agent 已经能规划、推理、执行多步任务了，但一到「付钱」环节就撞墙——没有合法身份、需要自主执行、凭证不安全、需要毫秒响应、需要微支付。传统支付系统（T+1 到 T+3）完全跟不上 Agent 的速度。 |
| [[Intent-Pay签意图模式]] | 🟢 | 传统支付是「每笔交易都签名」，Intent-Pay 是「签一个意图，Agent 自动执行」。用户签一次——比如「本月最多花 500 刀，单笔不超过 50 刀，不能赌博」——之后 Agent 就在这个范围内自主花钱。就像给 Agent 一张「额度卡」，而不是每次都帮你刷卡。 |
| [[AEP2协议]] | 🟡 | 把签名授权直接附在 HTTP 请求头里（`X-AEP2-Mandate`），先服务后结算。和 x402 的区别：x402 是「先付钱再服务」，AEP2 是「先授权再服务再结算」——对 Agent 来说，后者更高效，因为不用等链上确认。 |
| [[三阶段学习路线]] | 🟢 | 第一阶段：先理解以太坊这台机器（账户、交易、gas、EL、CL、节点）；第二阶段：进入协议资料（EPF Wiki、官方 specs、客户端仓库、公开笔记）；第三阶段：选择一个小方向深入（规格和测试、客户端实现、数据和证明）。 |
| [[贡献的五个层次]] | 🟢 | 整理资料 → 复现问题 → 参与讨论 → 提交小 PR → 形成项目。作为 Ops，我完全可以在第一层（整理资料、写中文笔记）和第三层（参与讨论、在 issue 里问问题）就开始贡献。 |
| [[Harness Engineering]] | 🟡 | FluxA 的风控引擎用了「约束工程」的思路——不是限制 Agent 不能做事，而是在控制范围内让它自由发挥。这和之前学的 Agent 安全、x402 协议的逻辑是一致的：**约束不是限制，而是赋能**。就像给小孩一个围栏——不是不让他跑，而是在安全范围内让他自由探索。 |
