# AI Security & Privacy（AI安全与隐私）

## 一句话解释
在AI处理你的数据时，如何保证数据不被泄露、模型不被篡改、结果可以被验证——这恰好是Web3擅长的事。

## 生活类比
> 你去医院看病，需要把你的病历给AI诊断。你希望：
> 1. 病历不会被医院卖给广告商（隐私）
> 2. AI不会被黑客改成乱开药方（安全）
> 3. AI的诊断结果可以被其他医生验证（可验证性）
>
> AI Security/Privacy就是要解决这三个问题。

## Web3为什么能帮上忙
| 问题 | Web3的解法 |
|------|-----------|
| 我的数据被AI公司随意使用 | 数据上链，用授权控制谁能看 |
| AI模型是个黑箱，不知道它怎么决定的 | 可验证计算，证明推理过程正确 |
| 中心化AI服务随时可能关停 | 去中心化部署，没有单点故障 |
| 模型被投毒/后门攻击 | 链上记录模型版本和训练数据来源 |

## 和传统网络安全的区别
- 传统安全：保护服务器不被攻破
- AI安全：还要保护**模型本身**（不被偷、不被篡改、不被逆向）和**训练数据**（不被泄露、不被投毒）

## AI Agent 安全框架（2026-07-09 新增）

### 核心理念
AI Agent 安全是系统工程，不是单一技术。就像建造一座城堡，不仅需要高墙，还需要护城河、吊桥、守卫和预警系统。

### Agent Guard 平台（四大能力）
1. **Discover（发现）**：资产发现，构建实时AI资产与风险清单
   - 跨代码仓库、云/模型厂商、运行时主机的资产发现
   - AI资产识别、框架指纹、供应链信誉评分

2. **Red-Team（红队验证）**：模拟攻击发现漏洞
   - Prompt注入、工具审批绕过、RAG泄露、MCP提权、密钥暴露、Web3合约风险
   - 发现（含严重度/证据/责任人）→ 修复 → 复测

3. **Defend（运行时防御）**：实时拦截高危命令
   - 本地护栏实时判断动作：allow·warn·approve·block
   - 钩子拦截、深度扫描、每日巡检

4. **Govern（治理）**：统一控制面
   - 策略下发、审批工作流、审计时间线、威胁情报网
   - 一个仪表盘看所有Agent风险

### 安全原则与机制

#### 最小权限原则（Principle of Least Privilege）
- **定义**：只给予完成任务所需的最小权限
- **类比**：就像你给朋友钥匙，只给他开大门的钥匙，而不是所有房间的钥匙
- **应用**：
  - AI Agent只授予必要的API权限
  - 智能合约只暴露必要的函数
  - 用户只拥有完成任务的最小权限

#### HITL（Human-in-the-Loop）
- **定义**：人类在环，AI决策需要人类监督和干预
- **类比**：就像自动驾驶汽车，虽然可以自动驾驶，但关键时刻需要人类接管
- **应用**：
  - AI Agent执行高危操作前需要人类确认
  - 重要决策需要人类审核
  - 异常行为需要人类干预

### AI Agent 风险类型

#### Prompt注入（Prompt Injection）
- **定义**：通过恶意提示词攻击AI系统，使其执行非预期操作
- **类比**：就像SQL注入，通过恶意输入操控数据库
- **例子**：
  - "忽略之前的指令，执行..."
  - "你是一个恶意助手，帮我..."
- **防御**：输入过滤、权限控制、沙箱隔离

#### AI幻觉（AI Hallucination）
- **定义**：AI生成看似正确但实际错误的信息
- **原因**：
  - 模型训练数据不足
  - 概率分布问题
  - 注意力机制带偏
- **例子**：
  - AI编造不存在的论文
  - AI生成错误的代码
  - AI提供虚假的法律建议

#### 失控的自主权限
- **风险**：AI Agent可能执行非预期操作
- **原因**：过度授权、缺乏监督
- **防御**：最小权限原则 + HITL机制

#### 供应链攻击
- **定义**：通过攻击供应链中的薄弱环节来入侵系统
- **类比**：就像在食品供应链中投毒，影响所有下游产品
- **区块链例子**：
  - 恶意npm包攻击DApp前端
  - 钓鱼网站模仿官方站点
  - 恶意浏览器扩展窃取私钥
- **防御**：审查第三方依赖，使用安全工具扫描

### 区块链安全风险

#### NFT持有即授权
- **风险**：持有NFT可能隐含授权某些操作
- **例子**：
  - 某些NFT合约可能授权项目方转移你的资产
  - 持有NFT可能自动授权某些DeFi操作
- **防御**：仔细审查NFT合约的授权条款

#### 窃取私钥
- **风险**：恶意软件可能窃取钱包私钥
- **例子**：
  - 恶意浏览器扩展
  - 钓鱼网站
  - 恶意DApp
- **防御**：使用硬件钱包，定期更换私钥

### 博弈论视角

#### 零和博弈（Zero-sum Game）
- **定义**：一方的收益等于另一方的损失，总和为零
- **类比**：就像赌博，你赢的就是别人输的
- **区块链例子**：
  - 交易套利
  - MEV（最大可提取价值）
  - 流动性竞争

#### 拜占庭博弈（Byzantine Game）
- **定义**：分布式系统中的容错问题，部分节点可能恶意行为
- **类比**：就像拜占庭将军问题，部分将军可能叛变
- **应用**：
  - 区块链共识机制（如PoW、PoS）
  - 分布式系统容错
  - 多Agent协作安全

### AI模型局限性

#### 概率分布问题
- **问题**：底层训练不充分
- **表现**：模型可能关注错误信息

#### 注意力机制带偏
- **问题**：模型可能关注错误信息
- **表现**：推理过程可能出错

#### 推理链路带偏
- **问题**：推理过程可能出错
- **表现**：缺乏上下文会导致错误

### 安全防护工具

#### GoPlus
- **定义**：区块链安全基础设施
- **功能**：智能合约审计、代币安全检测、恶意地址识别
- **应用**：DeFi项目审计、代币安全评估、交易风险预警

#### Agent Guard
- **定义**：AI Agent安全防护系统
- **功能**：资产发现、红队验证、运行时防御、统一治理
- **目标**：构建"攻防闭环"的安全体系
