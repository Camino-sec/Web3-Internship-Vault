# FluxA：AI-Native Payment Infrastructure

> 来源：EPF7 分享 · 嘉宾 Jack Xiao
> 整理：Luvia · 2026-07-08

---

## 一、一句话定位

**让 Agent 像人一样花钱，但比人更安全、更快、更可控。**

FluxA 是为 AI Agent 经济设计的支付基础设施——不是给 Agent 加一个「支付插件」，而是从零构建一整套 Agent 专用的支付轨道。

---

## 二、核心问题：为什么 Agent 付不了钱？

AI Agent 已经能规划、推理、使用工具、执行多步任务。但到了「付钱」环节——调付费 API、订机票、买订阅——它们就撞墙了。

| 需求 | 传统支付 | Agent 的现实 |
|------|---------|-------------|
| 身份 | 人类 ID / KYC | Agent 没有合法身份 |
| 授权 | 手动点击签名 | 需要自主执行 |
| 凭证 | 卡号填表单 | 放在 prompt 里不安全 |
| 速度 | T+1 到 T+3 | 需要毫秒级响应 |
| 粒度 | 最低 $0.50 | 需要 $0.001 微支付 |

> 💡 FluxA 填补了这个空白——从零为 Agent 设计的支付轨道。

## 四、产品详解

### 1. AgentCard — 一次性虚拟信用卡

**一句话**：给 Agent 一张专用虚拟卡，用完即毁，不泄露真实凭证。

**场景**：Agent 需要买一张 $450 的机票

**流程**：
1. Agent 判断需要购买 $450 的机票
2. 从 FluxA 钱包申请一张 AgentCard，锁定 $450
3. FluxA 即时发放一次性 Visa/Mastercard 卡号
4. Agent 在商家结账页填写卡号
5. 支付成功 → **卡自动销毁**，未用余额退回钱包

**关键特性**：
- 💰 **金额锁定**：不能被多收一分钱
- 🔥 **一次性使用**：用完过期，泄露的凭证毫无价值
- 🔒 **凭证不泄露**：真实用户金融数据永远不进入 Agent 上下文

### 2. Intent-Pay — 签意图，不签每笔交易

**传统方式**：每笔 $500 的扣款都要审批 → Agent 被打断

**Intent-Pay 方式**：签一次「最高 $2000 的机票、酒店」意图 → Agent 跑起来，风控引擎拦截偏离意图的交易

**授权资产 → 执行意图 → 风控引擎拦截偏离意图的交易**

### 3. AEP2 — Agent 嵌入式支付协议

**一句话**：把签名授权直接附在 HTTP 请求头里，先服务后结算。

**协议格式**：
```http
POST /v1/search HTTP/1.1
X-AEP2-Mandate:
{
    "amount": "0.80",
    "asset": "USDC",
    "payee": "agent_cmo",
    "sig": "0xa5_3f"
}
```

**五步核心流程**：
1. **Authorize**：付款方签名一次性授权（金额、条款、收款方）
2. **Verify**：收款方链下验证签名授权
3. **Serve**：Agent 立即收到服务，无需等链上确认
4. **Settle**：授权在定义的时间窗口内延迟结算
5. **Batch**：多个授权一起验证和结算 → 支持微支付

**Slogan**：Authorize First, Settle Later（先授权，后结算）

## 五、关键洞察

### 1. Agent 经济需要「新轨道」

传统支付是为人类设计的——需要 KYC、手动签名、信用卡号。Agent 没有这些能力，也不应该有。FluxA 的思路是：不改造旧轨道，而是建新轨道。

### 2. 「签意图」比「签交易」更高效

这和以太坊的 ERC-4337（Account Abstraction）思路类似：用户签一次意图，系统自动执行。Intent-Pay 把这个理念应用到了 Agent 支付场景。

### 3. AEP2 是「Agent 时代的 HTTP 支付层」

把支付授权嵌入 HTTP 请求头，就像把 JWT Token 嵌入请求一样自然。这让支付变成了 API 调用的一部分，而不是独立的流程。

### 4. 凭证安全是核心

Agent 的「记忆」和「上下文」可能被泄露。如果 Agent 持有真实的信用卡号，泄露就是灾难。一次性虚拟卡 + 用完自毁，从根本上解决了这个问题。

## 七、我的思考

### 对 Ops 的启发

FluxA 的传播点很清晰：
- 「给 Agent 一张信用卡，用完即毁」——这个概念普通人一听就懂
- 「签一次意图，Agent 自动花钱」——比「每笔交易都要签名」高效得多
- 「先服务后结算」——颠覆了传统「先付款后发货」的逻辑

### 开放问题

1. AgentCard 的 Visa/Mastercard 合作是怎么谈下来的？这需要支付牌照吗？
2. AEP2 的延迟结算如果 Agent 跑路了怎么办？信任机制是什么？
3. Intent-Pay 的风控引擎用的是 AI 还是规则引擎？
